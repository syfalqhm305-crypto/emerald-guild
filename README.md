# نقابة إميرالد — Emerald Guild Web Platform

نظام متكامل: موقع رئيسي + لوحة قيادة عليا + بنك النقابة + متجر مرتبط بالبنك.

## هيكل الملفات
```
index.html      → الموقع الرئيسي (عام) + زر دخول القائد/النواب
bank.html       → دخول عضو + دخول مسؤول البنك + لوحتا التحكم
store.html      → المتجر العام + دخول مسؤول المتجر + لوحة إدارة المنتجات
leader.html     → لوحة القيادة العليا (القائد + النواب)
css/style.css   → التصميم الموحّد (الهوية البصرية الخضراء الزمردية)
js/db.js        → طبقة البيانات (localStorage الآن، جاهزة للتحويل لـ Supabase)
js/main.js      → أدوات الواجهة: تنبيهات، نوافذ منبثقة، أصوات النقر، أنيميشن
assets/logo.png → شعار النقابة
```

## كلمات المرور الافتراضية (غيّرها فورًا بعد الرفع)
- القائد الأعلى (index.html → دخول القائد): `leader123`
- مسؤول البنك (bank.html): `bank123`
- مسؤول المتجر (store.html): `store123`
- عضو تجريبي: ID `1000001` / اللقب `العضو المؤسس` / باسورد `member123`

كل هذه القيم موجودة في `js/db.js` داخل دالة `_seed()` — عدّلها مباشرة قبل النشر،
أو غيّرها من داخل لوحة القيادة (leader.html) بعد أول تسجيل دخول.

## كيف تشتغل الآلية
- **البنك**: كل عضو له حساب مستقل (آيدي + لقب + باسورد) ما يشوفه غير هو ومسؤول البنك.
  مسؤول البنك يقدر يضيف/يعدل/يجمّد أعضاء، ويعتمد طلبات السحب/الإيداع/التحويل.
- **المتجر**: مفتوح للجميع بدون تسجيل دخول للتصفح. عند الشراء يُطلب من المستخدم
  تأكيد هويته (آيدي + لقب + باسورد) فيُنشأ طلب "قيد المراجعة" يظهر في:
  - لوحة تحكم مسؤول البنك (تبويب "طلبات المتجر")
  - لوحة تحكم مسؤول المتجر (تبويب "طلبات الشراء")
  عند قبول الطلب من أي منهما يُخصم المبلغ تلقائيًا من رصيد العضو في البنك،
  وتُفتح رسالة واتساب جاهزة لتأكيد الطلب مع العضو.
- **القيادة العليا**: القائد يتحكم بكل شيء — يضيف/يعزل نواب (لهم نفس صلاحياته)،
  يغيّر كلمات مرور وأرقام مسؤولي البنك والمتجر، ويدير كل الأعضاء مباشرة.

## الربط بقاعدة بيانات Supabase (الخطوة القادمة)
الملف `js/db.js` مبني بحيث كل دالة `async` بنفس شكل استعلام حقيقي، فقط:

1. أنشئ مشروع Supabase وجداول: `guild`, `members`, `deputies`, `admins`,
   `products`, `orders`, `transactions`, `requests`, `audit_log`.
2. فعّل مكتبة supabase-js في كل صفحة:
   ```html
   <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
   ```
3. في أعلى `db.js` عبّي:
   ```js
   const SUPABASE_URL = "https://xxxx.supabase.co";
   const SUPABASE_ANON_KEY = "xxxx";
   const supabase = window.supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY);
   ```
4. بدّل جسم كل دالة داخل `DB` (مثل `getMembers`, `addMember`, `adjustBalance`...)
   لتستخدم `supabase.from('members').select()/insert()/update()/delete()`
   بدل القراءة من `localStorage` — الأماكن معلّمة بتعليقات `TODO-SUPABASE`.
5. فعّل Row Level Security (RLS) في Supabase حتى يكون كل عضو يشوف بياناته فقط،
   وهذا يحل مشكلة الخصوصية بشكل حقيقي (حاليًا الخصوصية منطقية بالواجهة فقط
   لأن البيانات محلية على نفس الجهاز).
